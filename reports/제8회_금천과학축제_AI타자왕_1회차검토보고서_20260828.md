## 결론

금천 1회차 검토용 릴리스와 Mock NAS 기록 증거, 승인 UI 자동 검증 산출물을 준비했다.

일반 운영 EXE를 직접 실행하면 `device-profile.json` 및 `bootstrap-credentials.json`이 없어서 credential-required fail-closed로 종료되는 것이 정상이다. 1회차 UI 검토는 루트의 `금천_1회차검토_실행.cmd`를 사용한다. 이 실행기는 실제 운영 NAS나 운영 Credential을 사용하지 않고 합성 Credential, `127.0.0.1` 로컬 HTTPS Mock NAS, 임시 CA, 격리 런타임만 사용한다.

## Credential-required 팝업 원인

팝업 원인은 credential-free 금천 EXE가 장치 프로필과 bootstrap credential 없이 실행되었기 때문이다. 이는 운영 Credential이 없는 배포본을 잘못된 실행 경로로 실행했을 때 production fail-closed 정책이 작동한 정상 동작이다.

일반 UI/기능 검증은 운영 secret을 요구하지 않도록 `금천_1회차검토_실행.cmd`와 자동 E2E에서 합성 Credential + 로컬 Mock NAS를 사용하도록 분리했다. Production의 credential-required fail-closed는 제거하거나 우회하지 않았다.
