# 2026 일잘러 페스타 타자왕 현장 운영 매뉴얼

이 문서는 행사장에서 `일잘러 타자왕은 누구!?`와 `AI 타자왕을 이겨라!`를 운영하기 위한 현장용 안내서입니다.
운영자는 아래 순서대로 PC 설정, 기록 확인, CSV 백업, 회차 변경, 오류 대응을 진행하면 됩니다.

---

## 1. 배포 원칙

최종 배포는 반드시 `release` 폴더만 사용합니다.

작업폴더 전체를 압축하거나 배포하지 마세요. 작업폴더에는 테스트 파일, 임시 파일, 로그, 빌드 파일, 백업 파일이 남아 있을 수 있습니다.

각 PC에는 `release` 폴더를 로컬 디스크로 복사해 실행하는 것을 권장합니다. 최신 버전은 EXE 위치와 관계없이 PC별 설정·누락 기록·로그를 `%LOCALAPPDATA%\ThePMD\TypingKing2026`에 저장하므로, 여러 PC가 OneDrive 안의 같은 실행 폴더를 열어도 `config-DESKTOP...`, `records-DESKTOP...` 같은 충돌 복사본이 생기지 않도록 분리되어 있습니다. 기존 실행 폴더의 설정과 누락 기록은 첫 실행 때 로컬 저장소로 복사하며 원본은 삭제하지 않습니다.

배포 전 권장 확인:

```bash
npm run clean:release
npm run scan:pii
```

`scan:pii`가 실패하면 해당 배포본은 사용하지 말고, 개인정보 의심 파일을 정리한 뒤 다시 확인합니다.

## 2. 실행 파일 6종

`release` 폴더에는 아래 6개 실행 파일이 있어야 합니다.

| 실행 파일 | 용도 | 설치 PC |
| --- | --- | --- |
| `일잘러 타자왕은 누구.exe` | 일반 타자 테스트 진행 | 플레이어 PC |
| `AI 타자왕을 이겨라.exe` | AI 대결 타자 테스트 진행 | 플레이어 PC |
| `일잘러 타자왕은 누구_리더보드.exe` | 일반 타자 기록 순위 확인 | 리더보드 PC |
| `AI 타자왕을 이겨라_리더보드.exe` | AI 대결 기록 순위 확인 | 리더보드 PC |
| `타자왕 연습모드.exe` | 연습용(좌: 일잘러 / 우: AI 선택 플레이) | 플레이어 PC |
| `타자왕 연습모드_리더보드.exe` | 연습 기록 듀얼 보드(일잘러+AI) | 리더보드/플레이어 PC |

플레이어 PC에서도 리더보드를 실행할 수는 있지만, CSV 백업과 회차 변경은 리더보드 PC에서 진행하는 것을 권장합니다.

연습모드 규칙: 연습 기록은 `기록저장\연습회차` 전용 폴더에 저장되어 공식 회차와 완전히 분리됩니다. 연습 실행기는 공식 일차/회차 설정을 읽거나 바꾸지 않고(전용 설정 `config/config.practice.json`), 문구 변경/공유가 잠겨 있으며, 최초 1회 관리자 모드에서 [폴더 생성 및 검증]을 실행해야 합니다. 연습 기록은 공식 순위·시상·CSV 집계에 포함되지 않습니다.

## 3. PC ID와 역할

PC ID는 기록이 어느 PC에서 만들어졌는지 확인하기 위한 이름표입니다.

현장에서는 PC마다 서로 다른 PC ID를 사용해야 합니다.

예시:

| 역할 | 권장 PC ID |
| --- | --- |
| 플레이어 1 | `PC01` |
| 플레이어 2 | `PC02` |
| 플레이어 3 | `PC03` |
| 플레이어 4 | `PC04` |
| 플레이어 5~8 | `PC05`~`PC08` |
| 리더보드 1 | `PC09` |
| 리더보드 2 | `PC10` |

PC ID가 중복되면 사후 로그 확인이 어려워집니다.

## 4. OneDrive 연결 기준

모든 PC는 같은 회사 OneDrive 폴더를 바라봐야 합니다.

관리자 모드에서 아래 항목을 확인합니다.

| 항목 | 설명 |
| --- | --- |
| OneDrive 루트 | 회사 OneDrive의 가장 위쪽 폴더 |
| 기록 기본 폴더명 | 행사 또는 테스트 회차별 공통 폴더명 |
| 일차 | 예: `1일차` |
| 회차 | 예: `1회차` |
| PC ID | 현재 PC의 고유 ID |

예시 경로:

```text
%USERPROFILE%\OneDrive - <회사명>
%USERPROFILE%\OneDrive - <회사명> (1)
```

OneDrive 루트는 개인 이름이 들어간 하위 폴더가 아니라, 회사 OneDrive 전체 폴더를 선택합니다.

## 5. 폴더 생성 및 검증

관리자 모드에서 설정을 입력한 뒤 반드시 `[폴더 생성 및 검증]`을 실행합니다.

검증이 완료되면 아래 구조가 만들어집니다.

```text
기록 기본 폴더명
└─ 1일차
   └─ 1회차
      ├─ incoming
      │  ├─ typing
      │  └─ ai
      ├─ exports
      ├─ logs
      └─ admin_actions
```

각 폴더의 의미:

| 폴더 | 의미 |
| --- | --- |
| `incoming/typing` | 일반 타자왕 기록 저장 위치 |
| `incoming/ai` | AI 타자왕 기록 저장 위치 |
| `exports` | CSV 백업 파일 저장 위치 |
| `logs` | 폴더 구조 호환용(자동 운영 로그는 각 PC의 `data/logs`에만 저장) |
| `admin_actions` | 숨김, 수정, 회차 표시 초기화 기록 저장 위치 |

설정이 완료되지 않은 상태에서는 게임 시작이 차단됩니다.

차단 문구:

```text
기록 저장 폴더 설정이 완료되지 않았습니다.
관리자 모드에서 OneDrive 루트 폴더를 선택한 뒤 [폴더 생성 및 검증]을 먼저 실행해 주세요.
```

## 7. 플레이 진행 방식

### 일반 타자왕

1. `일잘러 타자왕은 누구.exe` 실행
2. 참가자 정보 입력
3. 개인정보 동의 체크
4. `[시작]` 클릭
5. Stage 1~3 진행
6. 결과 화면 확인
7. 일반 리더보드에서 기록 확인

### AI 타자왕

1. `AI 타자왕을 이겨라.exe` 실행
2. 참가자 정보 입력
3. 개인정보 동의 체크
4. `[시작]` 클릭
5. AI와 대결 진행
6. 결과 화면 확인
7. AI 리더보드에서 기록 확인

`[다시하기]`를 누르면 중단 시점까지의 기록을 저장한 뒤, 마지막에 입력한 개인정보를 기준으로 바로 다시 플레이합니다.

게임 도중 `[메인으로 가기]`를 눌러도 중단 시점까지의 기록이 저장됩니다. 일반 타자왕은 `중단`, AI 타자왕은 `중단 패배`로 표시되며 완주 기록보다 아래에 정렬됩니다. 입력 글자 수, 진행률, 경과시간은 버튼을 누른 시점을 기준으로 기록합니다.

## 8. AI 타수 표시 기준

AI는 내부적으로 일정 주기마다 랜덤 속도로 타이핑합니다.
이 랜덤 속도 정책은 유지됩니다.

단, 화면과 기록에 표시되는 AI 타수는 내부 랜덤 목표값이 아니라 실제 AI 입력 기준으로 계산합니다.

계산 기준:

```text
AI 타수 = AI가 실제로 입력한 글자 수 ÷ START 이후 실제 경과 시간 × 60
```

중요 기준:

| 상황 | 표시 기준 |
| --- | --- |
| 3, 2, 1 카운트다운 중 | `AI 타수: 대기 중` |
| START 이후 | 실제 AI 입력량 기준 타수 |
| 무입력 패배 | 참여자 진행률 0.0%, 평균 0타 |
| AI 승리 | AI 진행률 100.0%, 실제 AI 입력 기준 평균 타수 |
| 참여자 승리 | AI가 실제 진행한 비율과 실제 AI 입력 기준 평균 타수 |

기존 기록은 삭제하거나 수정하지 않습니다. 새 리더보드 표시 로직으로 안전하게 보여줍니다.

## 9. 리더보드 운영 방식

리더보드에는 현재 세션과 플레이 기록 수가 표시됩니다.

### OneDrive 충돌 방지 구조

- 참가 기록은 기존처럼 `1건 = 고유 JSON 1개`로 저장합니다. 여러 플레이 PC가 같은 파일을 수정하지 않습니다.
- 일반 리더보드는 `incoming/typing`, AI 리더보드는 `incoming/ai`를 읽기 전용으로 집계합니다.
- 자동 새로고침은 OneDrive 공유 로그나 heartbeat 파일을 생성하지 않습니다. 리더보드를 여러 대 실행해도 공유폴더에 쓰지 않습니다.
- 회차 상태와 공유 문구는 `_typingking_state` 아래 장치별 고정 파일을 사용합니다. 같은 PC에서 반복 저장해도 새 파일이 계속 쌓이지 않습니다.
- 기존 `_typingking_active_sessions`, `_active_sessions`, `_stage_text_versions` 파일은 삭제하지 않으며, 새 장치별 상태 파일이 아직 없을 때만 호환용으로 읽습니다.
- 공유 master CSV는 만들거나 수정하지 않습니다. CSV는 회차 종료 시 관리자가 수동 백업할 때만 `exports`에 생성됩니다.

참가 기록 JSON 자체는 순위 복구를 위한 원본이므로 행사 중 자동 병합·이동·삭제하지 않습니다. 4천 건 이상의 기록도 리더보드가 캐시해 반복 읽기 부담을 줄이며, 회차가 끝난 뒤 CSV 백업을 확인하고 일차/회차 폴더 단위로 보관합니다.

### 기존 불필요 파일 1회 정리

모든 PC를 같은 최신 `release` 버전으로 교체한 뒤, 관리자 모드에서 `[OneDrive 불필요 파일 정리]`를 한 번 실행할 수 있습니다.

- 삭제 대상: 구버전 자동 로그, heartbeat, 누적형 회차 상태 파일, 새 문구 스냅샷으로 대체된 구버전 문구 버전 파일
- 보존 대상: `incoming/typing`, `incoming/ai`, `admin_actions`, `exports`의 참가 기록·관리자 조치·CSV 백업
- 현재 선택한 일차·회차의 구버전 로그와 동기화 보조 파일을 정리합니다. 과거 회차도 정리하려면 해당 회차를 선택한 뒤 실행합니다.
- 구버전 프로그램이 섞여 있으면 새 장치별 상태 파일을 읽지 못하므로, 반드시 모든 PC를 먼저 교체합니다.

예시:

```text
현재 세션 10명 참가 중
1일차 1회차
```

여기서 `10명 참가 중`은 실제 고유 인원 수가 아니라 리더보드에 표시 중인 플레이 기록 수입니다.

예시:

| 상황 | 표시 |
| --- | --- |
| 1명이 10번 플레이 | `10명 참가 중` |
| A, B, C, D 각 1회 플레이 | `4명 참가 중` |
| D 기록을 숨김 처리 | `3명 참가 중` |

숨김 처리된 기록은 참가 중 숫자에서 제외됩니다.

타이틀 이미지와 표 컬럼은 스크롤해도 고정됩니다. 기록이 많을 때는 데이터 행만 위아래로 스크롤됩니다.

## 10. 개인정보 표시 기준

리더보드 화면에서는 개인정보를 마스킹합니다.

이름 마스킹:

| 원본 | 표시 |
| --- | --- |
| 가나다 | 가*다 |
| 가나다라 | 가*다* |
| Sample | S*m*l* |

휴대폰번호는 가운데 번호를 가려서 표시합니다.

예시:

```text
앞자리-중간번호-끝번호 → 앞자리-****-끝번호
```

관리자 인증 전 검색은 마스킹된 표시값 기준으로만 동작합니다.
관리자 인증 후에는 운영 확인을 위해 원본 이름과 원본 전화번호 검색이 가능합니다.

CSV에는 관리자 확인용 원본 개인정보가 포함됩니다. CSV 파일은 외부로 공유하지 마세요.

## 11. CSV 백업과 회차 변경

회차 또는 일차를 변경하기 전 현재 회차 기록을 CSV로 백업해야 합니다.

리더보드 관리자 모드에서 `[현재 회차 CSV 백업]`을 실행합니다.

중요 기준:

- 일반 기록이 있으면 일반 리더보드 CSV 백업 필요
- AI 기록이 있으면 AI 리더보드 CSV 백업 필요
- 일반/AI 기록이 모두 있으면 각각 백업 필요
- 기록이 0건인 회차는 백업 없이 회차 변경 가능
- 한 PC에서 최신 기록 전체를 백업했다면 다른 PC에서 다시 백업하지 않아도 됨
- CSV 백업 후 새 기록이 추가되면 다시 백업 필요

백업이 부족하면 회차 변경이 차단됩니다.

예시 문구:

```text
회차(일차)를 변경하기 전 일반 타자왕과 AI 타자왕 CSV 백업이 필요합니다.
각 리더보드 관리자 모드의 [현재 회차 CSV 백업] 버튼을 눌러주세요.
```

## 12. 회차 불일치 상황

리더보드 PC에서 `1일차 2회차`로 변경했는데 다른 플레이어 PC가 아직 `1일차 1회차`라면 해당 PC의 플레이는 차단됩니다.

안내 예시:

```text
1일차 2회차로 변경해 주세요!
```

모든 PC는 같은 기록 기본 폴더명, 같은 일차, 같은 회차를 사용해야 같은 리더보드에 기록이 모입니다.

## 13. 누락 기록 반영

OneDrive에 일시적으로 저장하지 못한 기록은 PC 내부 `local_queue`에 남을 수 있습니다.

관리자 모드의 `[누락 기록 반영하기]`를 실행하면 기록이 처음 만들어진 공식 일차·회차 또는 연습회차 폴더로 다시 올립니다. 회차가 바뀐 뒤 재시도해도 새 회차에 섞이지 않습니다.

공식 기록과 연습 기록은 PC 내부에서도 각각 `local_queue`, `local_queue_practice`로 분리되어 서로 섞이지 않습니다.

성공 기준:

- 대상 `incoming` 폴더에 JSON 파일 생성
- 파일 크기 0 초과
- JSON 읽기 가능
- `record_id` 일치
- 일반 기록은 `incoming/typing`, AI 기록은 `incoming/ai`에 저장

처리 결과는 각 플레이 PC 로컬 저장소의 `logs`, `data/processed`, `data/recovery`에 남습니다. OneDrive 공유폴더에는 운영 로그를 쓰지 않습니다.

## 14. 관리자 조치

리더보드 관리자 모드에서는 아래 조치를 할 수 있습니다.

| 기능 | 설명 |
| --- | --- |
| 숨기기 | 원본 JSON은 보존하고 리더보드/CSV 표시에서 제외 |
| 기록 수정 | 원본을 직접 고치지 않고 수정본을 새 표시 기록으로 적용 |
| 현재 회차 표시 초기화 | 현재 회차 표시만 초기화, 원본 JSON 보존 |

관리자 조치는 `admin_actions` 폴더에 남습니다.
원본 `incoming` JSON은 직접 수정하거나 삭제하지 않습니다.

## 15. 오류 발생 시 확인 순서

### 기록이 리더보드에 안 보일 때

1. 플레이어 PC와 리더보드 PC의 일차/회차가 같은지 확인
2. 기록 기본 폴더명이 같은지 확인
3. OneDrive 동기화가 완료됐는지 확인
4. 리더보드에서 `[새로고침]` 클릭
5. 관리자 모드의 동기화 상태에서 원본 파일 수와 반영 기록 수 확인
6. 필요 시 `[누락 기록 반영하기]` 실행

### 게임 시작이 안 될 때

1. 관리자 모드에서 OneDrive 루트 선택 확인
2. PC ID 확인
3. 기록 기본 폴더명 확인
4. 일차/회차 확인
5. `[폴더 생성 및 검증]` 다시 실행

### 회차 변경이 안 될 때

1. 현재 회차 기록이 있는지 확인
2. 일반 리더보드에서 `[현재 회차 CSV 백업]` 실행
3. AI 리더보드에서 `[현재 회차 CSV 백업]` 실행
4. 백업 후 새 기록이 추가됐으면 다시 백업
5. 백업 완료 후 회차 변경 재시도

## 18. 빌드 및 검증 명령

### 소스 저장소 최초 설정

GitHub에는 PC별 관리자 비밀번호가 들어 있는 실제 설정 파일을 올리지 않습니다. 새 PC나 새 작업 폴더에서는 아래 예시 파일을 복사한 뒤 `CHANGE_ME_BEFORE_EVENT`를 행사 전용 비밀번호로 변경합니다.

```powershell
Copy-Item config/config.example.json config/config.json
Copy-Item config/config.practice.example.json config/config.practice.json
```

실제 `config/config.json`, `config/config.practice.json`, 참가 기록, 로그, 실행파일은 Git 추적 대상이 아닙니다.

최종 배포본을 만들 때 사용합니다.

```bash
npm run test:logic
npm run build
npm run dist
npm run scan:pii
```

특정 이름이나 번호를 추가로 검사해야 한다면 `TYPINGKING_PII_NEEDLES` 환경변수에 `|`로 구분해 입력할 수 있습니다. 실제 개인정보 값은 소스 파일에 적거나 Git에 커밋하지 않습니다.

최종 확인:

- `release` 폴더에 실행 파일 6개가 있는지 확인
- `release/data/records.csv`가 헤더만 있는지 확인
- `release/data/admin_audit.csv`가 헤더만 있는지 확인
- 6개 실행 파일이 열리는지 확인
- 실제 OneDrive 환경에서는 행사 전 리허설로 리더보드 동기화 상태를 확인
