## Configuration boundary

`loadNasConfig(env)` accepts only these four named inputs:

- `NAS_EVENT_CONFIG`
- `NAS_TOKEN_MANIFEST`
- `NAS_DATA_ROOT`
- `NAS_PARTICIPANT_HMAC_KEY_FILE`

The loader:

- requires absolute paths;
- rejects unknown JSON keys at the configuration, session, AI-range, manifest, and token-entry levels;
- fixes the event ID, record folder name, official AI ranges, and practice AI ranges to the design values;
- rejects missing or duplicate official sessions and duplicate session IDs;
- rejects unknown or duplicate token sessions, token IDs, and token hashes;
- accepts only lowercase 64-character SHA-256 token hashes and never accepts a plaintext-token field;
- requires at least 32 bytes of participant HMAC material;
- verifies the event, token-manifest, HMAC, and configured phrase-catalog paths are files;
- rejects group/other-writable protected files on platforms where POSIX permission bits are exposed. This permission-bit check is intentionally skipped on Windows because the POSIX mode does not represent the Windows service ACL.

No secret value or path is included in thrown error messages.

## Authentication and rate limiting

`authenticateRequest(headers, manifest, now)`:

- accepts only exactly 256-bit tokens encoded as 64 lowercase hex characters or canonical unpadded base64url;
- hashes the supplied encoding with SHA-256;
- compares fixed 32-byte hash buffers with `timingSafeEqual` across the entire manifest;
- derives event scope from the fixed manifest rather than a client-controlled required event header;
- checks an event value when the trusted caller supplies one;
- binds the matched token to the `X-Device-Id` value;
- can enforce trusted caller-supplied required role and session context;
- checks expiration and revocation;
- returns only token ID, device ID, event ID, role, and allowed sessions;
- returns stable non-secret error codes: `AUTH_MISSING`, `AUTH_INVALID`, `AUTH_EXPIRED`, `AUTH_REVOKED`, `DEVICE_SCOPE`, `ROLE_SCOPE`, and `SESSION_SCOPE`.

`TokenBucketLimiter` implements a per-key token bucket. The tested operational values are burst 120 and refill 1/second (60/minute). `AuxiliaryIpLimiter` uses the same mechanism with the tested high ceiling of burst 2,400 and refill 40/second. The auxiliary limiter does not authenticate or identify a caller.

## Strict record normalization

`validateAndNormalizeRecord(body, authenticatedDevice, config, receivedAt)` rejects the request before normalization when:

- the canonical JSON body exceeds 32 KiB or contains a non-canonical/non-finite value;
- any envelope, record, participant, session, or stage field is unknown or missing;
- schema, event, writer role, authenticated device, record ID, or session scope differs;
- official day/round or practice session differs from the configured allowlist;
- timestamps are not real calendar timestamps or have invalid ordering;
- birthdate is not a real calendar date, the phone is not a Korean `010` mobile number, or consent is absent;
- stage order has a gap, or phrase ID/version/stage/text differs from the supplied authoritative catalog;
- official or practice AI CPM falls outside its exact stage-specific inclusive range;
- time is not a positive safe integer, typed text is not an exact prefix, or win/loss/interruption status is inconsistent;
- a client attempts to submit derivative fields.

The returned `StoredNasRecordV1` is rebuilt from validated fields and includes server-derived:

- normalized phone and phone/birth masks;
- HMAC-SHA256 participant key from the normalized phone;
- per-stage typing units;
- total typing units and total user time;
- exact effective CPM numerator and denominator plus display CPM;
- authenticated device ID and server received time;
- canonical request payload SHA-256.

Success requires exactly three `USER_WIN` stages. Failure or interruption permits only preceding completed wins plus the current losing/interrupted stage. Raw request objects are never returned as the stored record.
